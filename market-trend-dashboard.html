-- market-trend-dashboard — schedules the premarket-alert Edge Function to fire 3x/day, ~15 minutes -- before each major trading session opens, so the Telegram trend/signal summary goes out whether -- or not anyone has the dashboard open. -- -- Prerequisite: deploy the Edge Function first (see premarket-alert/index.ts's own header comment -- for the `supabase functions deploy premarket-alert` steps + secrets to set). This file only sets -- up the schedule that calls it — run it AFTER the function is deployed and you've confirmed the -- manual curl test in that file's header sends you a Telegram message. -- -- How it works: pg_cron runs a job on a schedule; pg_net lets a SQL job make an outbound HTTP call -- directly from Postgres. Together they let your database itself trigger the Edge Function — no -- separate server or always-on process needed. -- -- >>> Before running: replace YOUR-PROJECT-REF and YOUR-ANON-KEY below (2 places each, one per -- >>> session) with your actual Supabase project ref and anon key (same ones already in -- >>> market-trend-dashboard.html's SUPABASE_URL / SUPABASE_ANON_KEY constants). -- -- Session open times used (approximate, UTC, matches the dashboard's own session-strip logic — -- see getSessionStatus() in market-trend-dashboard.html): Asia 00:00, London 07:00, New York -- 12:00. Scheduled 15 minutes before each, Monday-Friday only (forex is closed weekends; the -- dashboard's own session strip doesn't track weekends either, so this keeps the same -- approximation rather than trying to be more precise than the app already is elsewhere). -- Cron time fields are minute/hour in UTC, and cron itself always runs in UTC regardless of your -- local time or the server's timezone. -- -- Want it to also fire on Sunday evening (when Sydney/Asia trading actually resumes for the new -- week) or skip a particular session?
